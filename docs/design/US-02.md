# Design: US-02 — Anonymous Visitor Discovers Login Requirement

> Temporary design doc. Delete after implementation is verified.

## Overview

Show a clear, Spanish-first call-to-action in the review form area for anonymous visitors. The goal is to explain how to participate without blocking review reading, and to send the visitor to the login page with a return URL back to the current business profile.

## Goals

- Replace the review form area with a guest CTA when no Supabase session exists
- Link to `/auth/login` with a `returnTo` parameter pointing back to the current business page
- Keep the CTA visually noticeable but secondary to the review list
- Reuse the existing `ReviewForm` component instead of introducing a new abstraction

## Non-Goals

- Implement full review submission behavior (US-05)
- Implement complete login or signup forms (US-03 / US-04)
- Add backend or database changes
- Add mobile-specific behavior

## Affected Areas

| Workspace | Files                            | Change                                                    |
| --------- | -------------------------------- | --------------------------------------------------------- |
| `web/`    | `src/components/review-form.tsx` | Add auth-aware conditional rendering and guest CTA        |
| `web/`    | `src/app/[slug]/page.tsx`        | Render `ReviewForm` in the reviews section below the list |
| `web/`    | `src/app/auth/login/page.tsx`    | Later story should honor `returnTo` on successful login   |
| `web/`    | `src/lib/supabase.ts`            | Reuse existing client to detect session; no API change    |

## UI Flow

```text
Business detail page
  └─ renders ReviewList (read-only for everyone)
  └─ renders ReviewForm area
       └─ ReviewForm checks Supabase session on the client
            ├─ no session → show CTA card with login link
            └─ session exists → hand off to the authenticated form behavior (US-05)
```

## Proposed Changes

### 1. `web/src/components/review-form.tsx`

Keep `ReviewForm` as the single owner of the review-entry area.

**Auth states:**

| State         | Trigger                    | Render                                    |
| ------------- | -------------------------- | ----------------------------------------- |
| Loading       | Initial client auth check  | Small skeleton or muted placeholder block |
| Anonymous     | No active Supabase session | CTA card with login button                |
| Authenticated | Session exists             | Actual review form (implemented in US-05) |

**Anonymous CTA content:**

- Title: `¿Quieres dejar tu reseña?`
- Body: `Inicia sesión para compartir tu experiencia y ayudar a otros clientes a decidir con confianza.`
- Primary action: `Iniciar sesión`
- Optional secondary link: `Crear cuenta`

**CTA URL:**

```ts
const returnTo = `/${businessSlug}#reviews`;
const loginHref = `/auth/login?returnTo=${encodeURIComponent(returnTo)}`;
```

Example:

```text
/auth/login?returnTo=%2Fpanaderia-la-esquina%23reviews
```

### 2. `web/src/app/[slug]/page.tsx`

Replace the current reviews placeholder area with the real review experience structure:

```tsx
<section
  id="reviews"
  className="bg-white rounded-xl border border-gray-200 p-6"
>
  <h2 className="text-lg font-semibold text-gray-900 mb-4">Reseñas</h2>
  <ReviewList businessSlug={slug} />
  <div className="mt-6 pt-6 border-t border-gray-100">
    <ReviewForm businessSlug={slug} />
  </div>
</section>
```

This keeps the reading experience first and places the CTA/form after the existing reviews.

### 3. Login redirect contract

No worker change is needed. The only contract for this story is the query parameter convention:

```text
/auth/login?returnTo=/{slug}#reviews
```

`US-04` should read `returnTo` from `searchParams` and redirect there after successful login. This story only needs to generate the correct link.

## UI / UX Notes

- Use shadcn/ui primitives such as `Card`, `Button`, and `Alert`-style messaging for consistency.
- Keep all copy in Spanish.
- The CTA should feel inviting, not blocking: warm wording, compact layout, and clear next step.
- Avoid showing the guest CTA above the review list; anonymous users primarily came to read first.
- Use a brief loading state while checking the session to avoid a flash of the wrong UI during hydration.

## Data / API Contract

No backend endpoint changes are required for this story.

The only new contract is a frontend navigation convention:

```ts
{
  pathname: '/auth/login',
  searchParams: {
    returnTo: `/${businessSlug}#reviews`
  }
}
```

## Testing Plan

### Manual / UI verification

- Anonymous visitor on `/{slug}` sees the CTA instead of the review form
- CTA button points to `/auth/login` and includes the encoded `returnTo` parameter
- Review list remains visible and readable above the CTA
- Logged-in users do not see the anonymous CTA
- All text is in Spanish and styling matches the existing card layout

### Future integration check

Once `US-04` is implemented, verify that logging in from the CTA returns the user to the same business page and lands near the reviews section.

## Risks / Open Questions

| Risk                                                                           | Mitigation                                                                               |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| The login page is still a stub today                                           | This story only depends on generating the correct link; redirect handling lands in US-04 |
| Client-side session lookup can briefly render the wrong state during hydration | Use an explicit loading state before showing anonymous or authenticated UI               |
| CTA could distract from reading reviews                                        | Place it below the list and keep the card compact                                        |
