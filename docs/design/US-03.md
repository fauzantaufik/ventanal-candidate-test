# Design: US-03 — Consumer Creates Account

> Temporary design doc. Delete after implementation is verified.

## Overview

Implement the signup experience at `/auth/signup` so an anonymous visitor can create an account with name, email, and password, then continue back to the business page they came from. The design should feel production-ready, stay Spanish-first, and rely on Supabase Auth as the system of record.

## Goals

- Build a complete signup form with `name`, `email`, and `password`
- Validate required fields, email format, and a minimum password rule before submit
- Create the account through `supabase.auth.signUp(...)`
- Redirect the user back to `returnTo` after success when a session is created, or show a confirmation state if email verification is required
- Keep the flow aligned with the `returnTo` convention introduced in US-02

## Non-Goals

- Backend or worker changes
- Review submission logic
- Password reset flow
- Social login providers
- Profile editing beyond initial `full_name` metadata

## Affected Areas

| Workspace | Files | Change |
|-----------|-------|--------|
| `web/` | `src/app/auth/signup/page.tsx` | Implement full client signup page |
| `web/` | `src/lib/supabase.ts` | Reuse existing Supabase client |
| `web/` | `src/app/auth/login/page.tsx` | Linked as the alternate auth path; redirect handling should stay consistent |
| `web/` | `src/components/review-form.tsx` | Existing guest CTA can route here as a secondary path |

## User Flow

```text
Anonymous visitor on business page
  └─ clicks "Crear cuenta" or opens /auth/signup
       └─ signup page reads ?returnTo=/{slug}#reviews
            └─ user submits name + email + password
                 ├─ client validation fails → show Spanish field errors
                 ├─ Supabase error → show Spanish error alert
                 └─ success
                      ├─ session created immediately → redirect to returnTo (or '/')
                      └─ email confirmation required → show success message with next steps
```

## Proposed Changes

### 1. `web/src/app/auth/signup/page.tsx`

Convert the stub into a client page (`'use client'`) with local form state.

**Fields:**
- `fullName`
- `email`
- `password`

**Validation rules (client-side):**
- `fullName`: required, trimmed, minimum 2 characters
- `email`: required, basic email format check
- `password`: required, minimum 8 characters

These are intentionally simple and shippable; Supabase remains the final authority.

**Submit behavior:**
```ts
await supabase.auth.signUp({
  email,
  password,
  options: {
    data: { full_name: fullName },
  },
});
```

After success:
- if Supabase returns a session, redirect to `returnTo ?? '/'`
- if session is null and confirmation is required, show a success card like:
  - title: `Revisa tu correo`
  - body: `Te enviamos un enlace para confirmar tu cuenta antes de continuar.`

### 2. `returnTo` handling

The page should read `searchParams` / `useSearchParams()` and preserve the return URL through the auth flow.

Example:
```text
/auth/signup?returnTo=%2Fpanaderia-la-esquina%23reviews
```

Redirect target after successful signup:
```ts
const destination = returnTo || '/';
router.replace(destination);
```

### 3. UI structure

Use shadcn/ui primitives for a polished but simple form:
- `Card` / `CardContent` / `CardHeader`
- `Input`
- `Label`
- `Button`
- `Alert` for errors

Suggested layout:

```text
┌────────────────────────────────────┐
│ Crear cuenta                      │
│ Únete para dejar reseñas...       │
│ [ Nombre completo              ]  │
│ [ Correo electrónico           ]  │
│ [ Contraseña                  ]   │
│ [ Crear cuenta ]                  │
│ ¿Ya tienes cuenta? Inicia sesión  │
└────────────────────────────────────┘
```

## UI / UX Notes

- Keep all copy in Spanish and friendly to a local consumer audience.
- Show inline validation below each field where useful.
- Disable the submit button and show a spinner text such as `Creando cuenta...` while the request is in flight.
- If signup fails, map the Supabase error into a human-friendly Spanish alert rather than dumping raw provider text.
- If `returnTo` is absent, default to `/`.

## Error Handling

Map common cases to simple Spanish copy:

| Situation | UI message |
|-----------|------------|
| Invalid email | `Ingresa un correo válido.` |
| Weak/short password | `La contraseña debe tener al menos 8 caracteres.` |
| Existing account | `Ya existe una cuenta con ese correo. Inicia sesión.` |
| Generic signup failure | `No se pudo crear la cuenta. Inténtalo de nuevo.` |

## Data / API Contract

No worker API changes are needed.

Supabase contract used by the page:

```ts
supabase.auth.signUp({
  email: string,
  password: string,
  options: {
    data: {
      full_name: string
    }
  }
})
```

Inputs/outputs that matter for the app:
- input: `full_name`, `email`, `password`
- output: `data.session` determines redirect vs confirmation state
- error: used to show Spanish failure copy

## Testing Plan

### Manual / UI verification

- The page shows `name`, `email`, and `password` fields
- Empty submit shows validation feedback in Spanish
- Invalid email and short password are blocked client-side
- Successful signup redirects to `returnTo` when a session is returned
- If email confirmation is required, a success state is shown instead of redirecting immediately
- Existing-account or provider errors surface as a readable Spanish message
- The page includes a link to `/auth/login`

### Future integration verification

Once login and review submission are implemented:
- Start from a business page CTA → create account → return to the same business page → continue toward leaving a review

## Risks / Open Questions

| Risk | Mitigation |
|------|------------|
| Supabase project may require email confirmation, preventing immediate auto-login | Design supports both outcomes: redirect when session exists, confirmation state when it does not |
| Raw Supabase errors may be too technical or in English | Normalize the most common cases into short Spanish messages |
| `returnTo` could be missing or malformed | Fallback safely to `/` |
