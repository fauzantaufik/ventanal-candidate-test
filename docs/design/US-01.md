# Design: US-01 — Anonymous Visitor Views Reviews

> Temporary design doc. Delete after implementation is verified.

## Overview

Enable anonymous visitors to see all reviews for a business on the detail page. This is read-only, no auth required. It's the first building block of the review system and delivers immediate value.

## Goals

- Display reviews for any business via a public API endpoint
- Show star rating, comment, reviewer name, and relative date (Spanish)
- Handle the State Triad: loading skeleton → data/empty → error with retry
- Support cursor-based pagination (10 per page, "load more")

## Non-Goals

- Review submission (US-05)
- Auth flows (US-03/04)
- Login CTA for guests (US-02)
- Mobile app changes

## Data Flow

```
[slug]/page.tsx (server component)
  └─ renders <ReviewList businessSlug={slug} /> (client component)
       └─ useEffect → getReviews(slug) 
            └─ hc<AppType> client.$get({ param: { slug }, query: { limit, offset } })
                 └─ Hono GET /businesses/:slug/reviews
                      └─ D1 query → reviews WHERE business_id = (SELECT id FROM businesses WHERE slug = ?)
                           └─ JSON response → render list or empty/error state
```

## Proposed Changes

### 1. Worker — `GET /businesses/:slug/reviews`

Route in `worker/src/routes/reviews.ts`, mounted at `/businesses` in `index.ts` (already done).

**Request:**
```
GET /businesses/:slug/reviews?limit=10&offset=0
```

**Response (200):**
```json
{
  "data": [
    {
      "id": "abc123",
      "user_name": "María López",
      "rating": 4,
      "comment": "Excelente servicio, muy recomendado.",
      "created_at": "2026-04-05T14:30:00Z"
    }
  ],
  "meta": {
    "total": 23,
    "limit": 10,
    "offset": 0
  }
}
```

- Fields returned: `id`, `user_name`, `rating`, `comment`, `created_at`
- Excludes `user_email`, `user_id`, `business_id` (not needed by frontend, avoid leaking PII)
- Ordered by `created_at DESC` (newest first)
- Default `limit=10`, `offset=0`

**Response (404) — business slug not found:**
```json
{ "error": "Negocio no encontrado" }
```

**Implementation notes:**
- Resolve slug → `business_id` via `SELECT id FROM businesses WHERE slug = ?`
- Return 404 if no business matches the slug
- Query reviews with `WHERE business_id = ? ORDER BY created_at DESC LIMIT ? OFFSET ?`
- Count total with `SELECT COUNT(*) FROM reviews WHERE business_id = ?`
- Keep the route chainable for Hono RPC type inference (use `.get('/:slug/reviews', ...)`)

### 2. Web — `src/lib/api.ts`

Add a `getReviews` function using the Hono RPC client:

```ts
export async function getReviews(
  slug: string,
  params?: { limit?: number; offset?: number }
): Promise<ReviewListResponse> {
  // Use hc client for /businesses/:slug/reviews
  const res = await client.businesses[':slug'].reviews.$get({
    param: { slug },
    query: {
      limit: String(params?.limit ?? 10),
      offset: String(params?.offset ?? 0),
    },
  });
  if (!res.ok) throw new Error(`Failed to fetch reviews: ${res.status}`);
  return (await res.json()) as ReviewListResponse;
}
```

Export inferred types: `ReviewListResponse`, `ReviewItem`.

### 3. Web — `src/components/review-list.tsx`

Client component (`'use client'`) implementing the State Triad:

**Props:**
```ts
interface ReviewListProps {
  businessSlug: string;
}
```

**States:**

| State | Trigger | Render |
|-------|---------|--------|
| Loading | Initial mount / refetch | 3 skeleton cards (pulse animation) using shadcn `Skeleton` |
| Error | API failure | Alert with message + "Reintentar" button |
| Empty | `data.length === 0` | Friendly message: "Este negocio aún no tiene reseñas. ¡Sé el primero!" |
| Data | Reviews loaded | List of review cards |

**Review card layout:**
```
┌──────────────────────────────────────┐
│ ★★★★☆                    hace 3 días │
│ "Excelente servicio, muy recomendado"│
│ — María López                        │
└──────────────────────────────────────┘
```

- Star rating: `★` (filled) / `☆` (empty) for 1–5 using Unicode
- Comment: displayed if present; omitted if null
- Reviewer name: `user_name`
- Relative date in Spanish: use a small helper (no heavy lib needed — compute from `Date.now() - created_at` and map to "hace X minutos/horas/días/semanas/meses")

**Pagination:**
- Fetch first 10 on mount
- Show "Cargar más reseñas" button if `offset + limit < total`
- Append new results to existing list on load-more click
- Button shows spinner while loading more

**shadcn/ui components to use:**
- `Card` — review card container
- `Skeleton` — loading placeholders
- `Alert` — error state
- `Button` — retry and load-more

## Relative Date Helper

Small utility function (inline in `review-list.tsx` or a tiny `lib/date.ts`):

```ts
function timeAgo(dateStr: string): string {
  const seconds = Math.floor((Date.now() - new Date(dateStr).getTime()) / 1000);
  const intervals: [number, string, string][] = [
    [31536000, 'año', 'años'],
    [2592000, 'mes', 'meses'],
    [604800, 'semana', 'semanas'],
    [86400, 'día', 'días'],
    [3600, 'hora', 'horas'],
    [60, 'minuto', 'minutos'],
  ];
  for (const [secs, singular, plural] of intervals) {
    const count = Math.floor(seconds / secs);
    if (count >= 1) return `hace ${count} ${count === 1 ? singular : plural}`;
  }
  return 'ahora mismo';
}
```

## Risks / Open Questions

| Risk | Mitigation |
|------|------------|
| Hono route chaining for `/:slug/reviews` may conflict with `/:slug` in businesses.ts | Mount reviews sub-routes under the same `/businesses` base in `index.ts` — Hono matches more-specific paths first. Verify with a quick test. |
| RPC type inference may not fully resolve for the new reviews route if validator middleware isn't used | Use `zValidator` from `@hono/zod-validator` for query params, or export a manual type as fallback (see `api.ts` pattern for `BusinessesQuery`). |
| D1 `datetime('now')` stores UTC strings — relative date math must account for this | `timeAgo` helper works with UTC strings via `new Date(dateStr)` which parses ISO 8601. |
