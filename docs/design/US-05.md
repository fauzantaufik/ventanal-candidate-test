# Design: US-05 — Authenticated Consumer Submits Review

> Temporary design doc. Delete after implementation is verified.

## Overview

Enable authenticated consumers to leave a 1–5 star review with an optional comment on the business detail page. The implementation should reuse the existing `ReviewForm` placeholder, call the worker `POST /businesses/:slug/reviews` endpoint with the Supabase JWT, and refresh the visible business rating + review list immediately after a successful submission.

## Goals

- Show the real review form only to authenticated users
- Support a 5-star interactive picker and optional comment textarea
- Enforce the 500-character limit with a live counter
- Disable submit until a rating is selected
- Show loading, success, duplicate, and error states in Spanish
- Refresh the business summary and review list after submission
- Hide or lock the form after a successful review so the user cannot submit twice

## Non-Goals

- Editing or deleting a review after submission
- Photo uploads, moderation, or business replies
- Mobile review submission work
- A separate review-management dashboard

## Data Flow

```text
Business detail page
  └─ renders review section
       ├─ <ReviewList businessSlug={slug} />   (already implemented)
       └─ <ReviewForm businessSlug={slug} />
            └─ checks Supabase session
                 ├─ no session → show guest CTA (US-02 behavior)
                 └─ session exists → show rating + comment form
                      └─ on submit:
                           get access_token from Supabase session
                             └─ POST /businesses/:slug/reviews
                                  └─ worker validates JWT + payload + uniqueness
                                       └─ D1 insert + business aggregate update
                                            └─ 201 response → UI success + refresh
```

## Proposed Changes

### 1. `web/src/components/review-form.tsx`

Implement the real client form in the existing component.

**States:**

| State                      | Trigger                                      | Render                       |
| -------------------------- | -------------------------------------------- | ---------------------------- |
| Loading auth               | Initial session lookup                       | Small placeholder / skeleton |
| Anonymous                  | No active session                            | Login CTA from US-02         |
| Authenticated              | Session exists and user has not reviewed yet | Full review form             |
| Submitting                 | POST in flight                               | Disabled form + spinner copy |
| Success / Already reviewed | 201 or 409                                   | Locked confirmation card     |
| Error                      | 400/401/500 or network failure               | Alert with retry guidance    |

**Form fields:**

- `rating` (required, 1–5)
- `comment` (optional, max 500 chars)

**Interactive behavior:**

- five clickable star buttons
- hover preview for rating selection
- textarea character counter like `123 / 500`
- submit disabled when `rating` is unset or request is in flight

### 2. `web/src/lib/api.ts`

Add a typed helper for review creation:

```ts
export async function submitReview(
  slug: string,
  payload: { rating: number; comment?: string },
  token: string,
): Promise<SubmitReviewResponse> {
  const res = await fetch(`${API_URL}/businesses/${slug}/reviews`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${token}`,
    },
    body: JSON.stringify(payload),
  });
  // map 401 / 409 / validation errors into friendly exceptions
}
```

This keeps the token-attachment logic in one place and makes `ReviewForm` simpler.

### 3. `worker/src/routes/reviews.ts`

Extend the existing reviews route with:

```http
POST /businesses/:slug/reviews
Authorization: Bearer <jwt>
Content-Type: application/json
```

Validation rules:

- `rating` required, integer 1–5
- `comment` optional, string, max 500 characters

On success:

1. resolve `slug` → `business_id`
2. insert review row using authenticated user identity
3. recalculate `avg_rating` and `review_count` on the `businesses` table
4. return `201` with the created review payload

### 4. Immediate UI refresh after submission

The page currently renders the business header as a server component and `ReviewList` as a client component. To satisfy the “update immediately” requirement without converting the whole page to client-side rendering:

- keep `BusinessPage` server-rendered
- let `ReviewForm` call `router.refresh()` after a successful submission to update the header rating summary
- optionally use a tiny coordinating client wrapper (for example `BusinessReviewsSection`) if implementation needs a clean way to tell `ReviewList` to refetch after `onReviewSubmitted`

This is the smallest acceptable coordination layer for the current architecture.

## API Contract

### Request

```json
{
  "rating": 5,
  "comment": "Excelente atención y entrega rápida."
}
```

### Success response (201)

```json
{
  "success": true,
  "data": {
    "id": "rev_123",
    "user_name": "María González",
    "rating": 5,
    "comment": "Excelente atención y entrega rápida.",
    "created_at": "2026-04-10T14:30:00Z"
  },
  "business": {
    "avg_rating": 4.3,
    "review_count": 8
  }
}
```

### Error responses

- `400` → invalid rating or comment too long
- `401` → missing/expired/invalid JWT
- `404` → business slug not found
- `409` → user already reviewed this business
- `500` → unexpected server error

## UI / UX Notes

- Use Spanish copy throughout.
- Keep the form below the review list so visitors can read first, then contribute.
- On successful submission, replace the form with a confirmation card such as `¡Gracias por compartir tu experiencia!`.
- If the API returns `409`, show a calm locked state: `Ya dejaste una reseña para este negocio.`
- For `401`, route the user back to `/auth/login?returnTo=/{slug}#reviews`.

## Testing Plan

### Worker (Vitest)

Add / extend tests for:

- successful `POST /:slug/reviews` returns `201`
- invalid `rating` returns `400`
- too-long `comment` returns `400`
- missing token returns `401`
- unknown slug returns `404`
- second review by same user returns `409`
- `businesses.avg_rating` and `review_count` update after insertion

### Web (manual / UI)

- Logged-in user sees the form instead of the guest CTA
- Star picker is interactive and submit stays disabled until a rating is selected
- Comment counter updates live and blocks >500 characters
- Submit shows a loading state
- Success state appears and the form no longer allows another submission
- The visible rating summary and review list refresh immediately after submit

## Risks / Open Questions

| Risk                                                                           | Mitigation                                                                                     |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| The page mixes a server-rendered business header with client review components | Use `router.refresh()` plus the existing `onReviewSubmitted` callback to keep the change small |
| Users may click submit more than once quickly                                  | Disable the button while submitting; backend uniqueness still remains the source of truth      |
| The repo may not yet have shadcn/ui primitives scaffolded                      | Add only the minimal input/button/card subset needed for the form                              |
